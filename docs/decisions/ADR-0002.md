# ADR-0002: Prisma as the ORM

## Status

Accepted

## Context

The application needs a layer between TypeScript code and PostgreSQL. Options range from raw SQL to fully abstract ORMs. Key constraints:

- TypeScript strict mode — we want type safety on query results, not `any`
- Auth.js v5 has a first-class `@auth/prisma-adapter` that expects a Prisma client
- Schema-first development fits the learning goal better than SQL-first (the schema file is a readable single source of truth)
- Migrations must be tracked in git — no schema drift between environments

## Decision

**Prisma 6** (`prisma@^6`, `@prisma/client@^6`).

Pinned to v6 specifically because Prisma 7 (released mid-2025) introduced a breaking architectural change: the `url` field was removed from the datasource block in `schema.prisma`, requiring a new `prisma.config.ts` driver pattern. This is not yet well-documented in combination with Auth.js v5. Upgrade to v7 when explicit compatibility guidance exists.

## Consequences

**What this enables:**
- Type-safe query API generated from the schema — TypeScript knows the exact return type of every query
- `prisma migrate dev` generates reviewed SQL migration files committed to git
- Auth.js adapter integration is first-class — `@auth/prisma-adapter` works against our client directly
- Prisma Studio gives a visual database browser for development

**What this forecloses:**
- Raw SQL flexibility for complex queries is reduced (still possible via `$queryRaw` with `Prisma.sql` tagged templates, which are injection-safe)
- Drizzle ORM's lighter-weight approach and smaller bundle

**Operational burden added:**
- Schema changes require a `pnpm db:migrate` step to generate and apply the migration. This adds a manual step but also adds a safety gate — you review the generated SQL before it runs.
- Prisma client must be regenerated after schema changes (`db:migrate` does this automatically).

**New risks:**
- Prisma 7 is available and pnpm will suggest the upgrade in install output. The upgrade must not be taken until Auth.js adapter compatibility is confirmed.

## Alternatives considered

**Drizzle ORM:** SQL-first, closer to raw SQL than Prisma. Stronger TypeScript inference in some edge cases, no code generation step, smaller runtime footprint. Would be a good choice for a team already fluent in SQL who wants minimal abstraction. We chose Prisma because the schema-first model is more readable when learning, and the Auth.js adapter ecosystem is mature.

**Raw SQL with `pg` or `postgres.js`:** Maximum control and performance. No abstraction overhead. Ruled out because we lose compile-time type safety on query results, and writing migrations by hand is error-prone without tooling.

**Kysely:** Query builder (not a full ORM) — you write SQL-like syntax in TypeScript and get type-safe results. More explicit than Prisma, good for complex queries. No first-class Auth.js adapter. Would require more boilerplate for the auth tables.
