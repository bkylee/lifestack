# ADR-0005: single environment (prod) deployed in v1. Dev/staging scaffolded but not provisioned

## Status
Accepted

## Context
Single env vs split environment. Use of shared root module or Terragrunt.
As this is a solo project, cost will be a major factor in my decisions. There are currently no large migrations or changes that would justify having separate environments.

## Decision
Regarding prod-only deployment: we created and deployed the RGs and resources for prod in v1. To cut costs, we will only deploy prod and save the scaffolding for dev and staging for later when we require them with a large change.

Regarding Terragrunt and shared root module: we have decided not to use either as both are unnecessary for the current scale of the project. Later, when there is enough code that would be affected, we can implement the shared root module.

## Consequences
Regarding Terragrunt and shared root module: later it will be extra work to rewrite the tf files to implement either of them, but not worth the extra work now since the scale is still small.

Having a single env means changes will affect the prod environment right away without testing.

I do understand that I will be limiting my full learning of what an enterprise environment would be like by limiting to one production env.

## Alternatives considered
Running all 3 envs = 3 times the resources running. This adds up in costs quickly when we aren't using them.

Terragrunt and shared root module can be useful but there isn't enough code affected by these to justify implementation currently.
