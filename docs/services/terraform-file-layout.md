# Terraform — environment directory layout

Reference for the files inside each `infra/environments/<env>/` directory: what each one is for and how they relate. For the Terraform service as a whole — state backend, naming convention, operations, gotchas — see [`terraform.md`](terraform.md).

## How Terraform reads a directory

Terraform loads **every `.tf` file** in a directory and merges them into one configuration before doing anything; declaration order across files does not matter. Splitting a config into `versions.tf`, `backend.tf`, `main.tf`, and so on is purely for human navigation — the filenames are community convention, not anything Terraform enforces. A single 200-line `main.tf` would behave identically.

One directory Terraform operates on = one **root module** = one state file.

## The files

Each `infra/environments/<env>/` directory holds these seven files:

| File | Purpose |
|---|---|
| `versions.tf` | Pins the toolchain. `required_version` constrains the Terraform CLI; `required_providers` declares each provider (azurerm, random) and its version bound. `~> 4.0` is the pessimistic constraint — "any 4.x, never 5.0." The *exact* versions resolved within those bounds are frozen in `.terraform.lock.hcl`. |
| `backend.tf` | Declares **where state lives** — the `stlifestack9k3l` storage account, `tfstate` container. The `key` names the state blob and is the one value that **must** be unique per environment; two directories sharing a key corrupt each other's state. `use_azuread_auth = true` authenticates with an Azure AD identity instead of a storage account key. |
| `main.tf` | Configures the `azurerm` **provider instance** — the target subscription and the `features {}` block (provider-wide behavior toggles). Holds no resources despite the name; "main.tf" here is convention by habit. |
| `variables.tf` | The input **interface** — declares what the directory accepts from outside (currently just `subscription_id`: name, type, description). No values. |
| `terraform.tfvars` | The input **values** — auto-loaded by Terraform, supplies `subscription_id`. Committed; holds no secrets. |
| `locals.tf` | Internal **named values** — `project`, `environment`, `location`, `base_tags`, `rg_names`. Not inputs; fixed inside the config. |
| `resource_groups.tf` | The actual infrastructure — one `azurerm_resource_group` block, `for_each` over `local.rg_names`, producing the four tier resource groups. |

After `terraform init`, two generated artifacts also appear:

| Artifact | Committed? | What it is |
|---|---|---|
| `.terraform.lock.hcl` | **Yes** | Pins exact provider versions and checksums across machines and CI. |
| `.terraform/` | No (gitignored) | Local working dir — downloaded provider binaries, backend metadata. Regenerated by `init`. |

## variables vs. locals vs. tfvars

These three are easy to blur. The distinction:

- **`variables.tf`** is the *contract* — the schema of what can be passed in. It says a `subscription_id` string is accepted; it does not say what that value is.
- **`terraform.tfvars`** is the *values* — what actually gets passed in for this directory's run. Separating it from the contract lets the schema stay stable and shared while values vary per environment or (when sensitive) come from elsewhere.
- **`locals.tf`** is *internal* — values computed or fixed inside the config, never passed from outside. `environment = "dev"` is a local because it is a fixed property of the directory, not something you would vary per invocation.

Rule of thumb: if a value could legitimately change between two runs of the *same* directory, it is a variable; if it is constant for that directory, it is a local.

## What varies between environments

Light duplication (`docs/mentor/m1-s3-multi-env-scaffolding.md`, [D1]; recorded formally in ADR-0005) means `prod/`, `dev/`, and `staging/` are near-identical copies. Exactly **two lines** differ per directory:

| File | prod/ | dev/ | staging/ |
|---|---|---|---|
| `backend.tf` | `key = "prod.tfstate"` | `key = "dev.tfstate"` | `key = "staging.tfstate"` |
| `locals.tf` | `environment = "prod"` | `environment = "dev"` | `environment = "staging"` |

Everything else — `versions.tf`, `main.tf`, `variables.tf`, `terraform.tfvars`, `resource_groups.tf`, and the rest of `locals.tf` — is byte-identical. The `${local.environment}` interpolation in `rg_names` propagates that one label into every resource name automatically. Keeping the three directories in sync by hand is the maintenance cost light duplication trades for; it is paid at code-review time.

## Refactor path: extracting a shared module

Light duplication is not the permanent state — it has a planned successor. When per-env HCL grows past roughly 80–150 lines (likely at Module 2, network), maintaining three hand-synced copies stops being cheap, and the resources should move into a **shared module**.

The refactor: pull the duplicated resource code out of the env directories into one reusable **child module** under `infra/modules/`, and reduce each env directory to a thin *caller* of it. (Terraform vocabulary: `modules/foundation/` becomes a *child module*; the env directories stay *root modules*. "Shared module" is shorthand for "the env roots all call one shared module.")

```
Light duplication (now)              Shared module (later)
environments/                        modules/
  prod/    resource_groups.tf          foundation/  main.tf variables.tf outputs.tf
  dev/     resource_groups.tf        environments/
  staging/ resource_groups.tf          prod/    main.tf  <- thin caller
  (resource code copied 3x)            dev/     main.tf  <- thin caller
                                       staging/ main.tf  <- thin caller
                                       (resource code lives once)
```

The resource declaration moves into `modules/foundation/`, parameterized by input variables:

```hcl
# modules/foundation/variables.tf
variable "project"     { type = string }
variable "environment" { type = string }
variable "location"    { type = string }

# modules/foundation/main.tf — the resource code, now written once
resource "azurerm_resource_group" "rg_names" {
  for_each = local.rg_names    # local.rg_names built from the input variables
  name     = each.value
  location = var.location
  tags     = local.base_tags
}
```

Each environment directory shrinks to a short caller:

```hcl
# environments/prod/main.tf
module "foundation" {
  source      = "../../modules/foundation"
  project     = "lifestack"
  environment = "prod"
  location    = "eastus2"
}
```

Note the variables/locals shift: today `environment` and `location` are *locals*; in the module they become *variables*, because they are now genuinely passed in from outside. Derived values like `rg_names` stay locals inside the module.

**What does not get DRYed.** Each env keeps its own `backend.tf` (a `backend` block cannot live in a child module and cannot take variables — so each env still hand-declares its unique state `key`), its `provider` block, and `versions.tf`. The env directories remain; they are no longer pure boilerplate, since each owns a unique state pointer.

**The migration gotcha.** Moving a resource into a module changes its state address (`azurerm_resource_group.rg_names["network"]` → `module.foundation.azurerm_resource_group.rg_names["network"]`). Without intervention `terraform plan` reads that as destroy-and-recreate. A `moved {}` block tells Terraform it is a relocation, making the plan a no-op:

```hcl
moved {
  from = azurerm_resource_group.rg_names
  to   = module.foundation.azurerm_resource_group.rg_names
}
```

**The trade-off.** A shared module trades *duplication* for *indirection* — one authoritative copy, impossible to drift between envs, at the cost that reading "what does prod deploy" means following a module call into `infra/modules/`. Below ~40 lines per env the indirection costs more than it saves; past ~150 it is the other way around. ADR-0005 records light duplication as the v1 choice and this extraction as its documented trigger.

## What is *not* in dev/ and staging/

`dev/` and `staging/` are **scaffold-only** in v1 — structured but never `terraform init`-ed or applied (see ADR-0005 for the triggers that would activate them). A clean scaffold directory contains only the seven hand-written files above: no `.terraform/`, no `.terraform.lock.hcl`, no state. Those artifacts appear the first time the environment is genuinely initialized, if a trigger ever fires.
